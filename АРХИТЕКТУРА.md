# Приложение «Расписание» — архитектура и техническое задание

> Документ для исполнителя (Sonnet 5.5). Здесь описано **что** строить и **как проверить**, что построено правильно.
> Все факты о файле расписания проверены на реальном `мое расписание.xlsx` (осенний семестр 2026–2027).
> Владелец проекта знает основы Python (аннотации типов, рекурсия) и только начинает программировать. Поэтому код должен быть простым, с понятными именами и короткими комментариями на русском. Каждый этап завершается инструкцией «как запустить и проверить».

## 1. Исходные данные

### 1.1 Общие правила для всех листов

- Листы для разбора: `ОФО`, `ОЗФО`, `Магистратура ОФО`. Лист `Шаблон` пропускаем. Список листов задаётся в `config.json`, а не в коде.
- На листе может быть несколько **блоков** (обычно по курсам). У каждого блока свой столбец «Дни недели», а сразу справа от него — столбец «Часы».
- **Пара = 2 строки** (обычно столбец «Часы» объединяет их, например `B8:B9`).
  - **Верхняя строка = 1 неделя, нижняя = 2 неделя.**
  - Если ячейка занятия объединена на обе строки (или в обеих строках одинаковый текст), занятие идёт каждую неделю.
  - Если занятие есть только в одной строке, оно проходит только в эту неделю.
- «Часы» обозначают пары: `1-2` → 1 пара, `3-4` → 2, `5-6` → 3, `7-8` → 4, `9-10` → 5. Формула: `пара = второе_число // 2`.
- Дни: «понедельник» … «суббота», в разном регистре («понедельник» / «Понедельник»). Название дня — объединённая ячейка на все строки дня.
- **Ширина объединённой ячейки показывает, для кого занятие:**
  - покрывает столбцы **больше чем одной группы** → **лекция**;
  - в пределах одной группы (вся группа или одна подгруппа) → **практика**;
  - текст содержит «Физическая культура» → тип `pe`, а пометки «(юноши)» / «(девушки)» становятся тегами `male` / `female`;
  - текст содержит «Кураторский час» → тип `curator`.
- Текст ячейки — `Предмет Фамилия И.О. Аудитория`; внутри могут быть переносы строк и двойные пробелы.
- Пустая ячейка или ячейка из одного пробела (`' '`) = пары нет.

### 1.2 Лист «ОФО» (очная форма)

| Строка | Содержимое |
|---|---|
| 1–3 | Шапка («Расписание учебных занятий…», «Утверждаю») |
| 5 | Курсы: `1 КУРС` (B5:X5), `2 курс` (AA5:AP5), `3 КУРС` (AR5:BD5), `4 КУРС` (BF5:BN5) |
| 6 | Группы, обычно объединены на 2 столбца: `1 БИ-25 (30)` = AA6:AB6. В скобках число студентов, при разборе отбрасывается |
| 7 | Подгруппы: AA7 = `БИ-25-1` (1-я подгруппа, левый столбец), AB7 = `БИ-25-2` (2-я) |
| 8–61 | Пары: понедельник…суббота, по 4–5 пар в день, по 2 строки на пару |

Столбцы «Дни недели»: **A, Y, AQ, BE**.

Особые случаи:
- `ИБ-26` (G6:H6) — строка 7 объединена (G7:H7) и пустая, то есть **подгрупп нет**: группа из одной подгруппы занимает 2 столбца.
- `ИТиСС-23` (BM6:BN6) — в строке 7 нет подписей. Если в обоих столбцах всегда одинаковые занятия, подгруппы схлопываются в одну (см. алгоритм, шаг 6).
- Всего на листе **29 групп**.

### 1.3 Лист «ОЗФО» (очно-заочная форма)

| Строка | Содержимое |
|---|---|
| 5 | Курсы: 1 (A5:L5), 2 (M5:S5), 3 (T5:X5), 4 (Y5:AC5), **5** (AD5:AG5) |
| 6–7 | Группы, **объединены по вертикали на 6–7**: `ОЗ-БИ-26 (24)` = C6:D7. **Отдельной строки подгрупп нет** |
| 8–27 | Только **пятница и суббота**, по 5 пар, 2 строки на пару |

Столбцы «Дни недели»: **A, M, T, Y, AD**.
- Если группа занимает 2 столбца (`ОЗ-1 ИТиСС-26`: G:H), это 2 подгруппы без подписей: «Подгруппа 1» и «Подгруппа 2». Если 1 столбец (`ОЗ-ИБ-25`: Q) — подгрупп нет. Если в обоих столбцах всегда одно и то же (`ОЗ-БИ-26`: C:D), подгруппы схлопываются в одну (шаг 6 алгоритма).
- Всего **17 групп**.

### 1.4 Лист «Магистратура ОФО»

| Строка | Содержимое |
|---|---|
| 1–3 | Шапка (A1:E3) |
| 4 | «Дни недели» (A4:A6), «Часы» (B4:B6), `1 КУРС (МАГИСТРАТУРА)` (C4:E4) |
| 5 | Группы, **по одному столбцу**: C5 `М-БИ-26 (16)`, D5 `М-ИВТ-26 ()`, E5 `М-БИ-25 ()`, F5 `М-ИВТ-25 ()` |
| 7–54 | Пары, понедельник–суббота, 4 пары в день |

- Скобки бывают пустыми (`()`) — их тоже отбрасываем.
- Подпись курса покрывает не все группы (F5 вне C4:E4), поэтому **курс вычисляем по году в названии группы, а не по шапке** (см. 1.6).
- В субботу `F47` и `F49` заполнены только в верхней строке, то есть это занятия только 1-й недели.
- Всего **4 группы**. `ws.max_column` = 103, но данные заканчиваются на F: пустые столбцы просто игнорируются.

### 1.5 Опечатки в источнике (парсер должен их пережить)

- `Аюбов. С-М.` — точка после фамилии.
- `Базаев А.А` — нет точки в конце и нет аудитории.
- `Батаева П.С.2-05` — аудитория без пробела.
- `читальный зал (1 этаж)`, `3 корпус` — аудитории не в формате `Ч-ЧЧ`.
- `Аккаутинг`, `проодаж`, `специальсность`, `Интерет-трейдинг` — опечатки в названиях предметов. Исправляем только через словарь в `config.json` (`subjectFixes`), а не правками в коде.

### 1.6 Календарь учебного года

**Чередование недель** (по официальной таблице) идёт без сбоев с 31.08.2026 по 17.07.2027, включая новогодние праздники:
```
неделя(дата) = ((дата − weekAnchor).days // 7) % 2 + 1        weekAnchor = 2026-08-31 (понедельник)
```
Формула проверена на всех 46 неделях таблицы. Контрольные значения:

| Дата | Неделя |
|---|---|
| 31.08.2026, 05.09.2026, 14.09.2026, 12.10.2026, 04.01.2027, 05.07.2027 | 1 |
| 07.09.2026, 05.10.2026, **08.10.2026**, 28.12.2026, 02.01.2027, 12.07.2027 | 2 |

**Звонки** (одинаковые во все дни, включая субботу; подтверждено владельцем):

| Пара | Время |
|---|---|
| 1 | 09:00–10:30 |
| 2 | 10:40–12:10 |
| — | большая перемена 12:10–13:00 |
| 3 | 13:00–14:30 |
| 4 | 14:40–16:10 |
| 5 | 16:20–17:50 |

Часовой пояс — `Europe/Moscow` (UTC+3, переходов на летнее время нет).

**Курс по названию группы:** `курс = год_начала_уч_года − (2000 + ГГ) + 1`, где `ГГ` — две цифры после дефиса (`БИ-25` → 2026 − 2025 + 1 = **2**).

## 2. Общая схема

```
  WhatsApp                       GitHub-репозиторий (бесплатно)
  ┌──────────┐ владелец кладёт  ┌──────────────────────────────────────────────┐
  │ xlsx     │ ───────────────▶ │ data/sources/raspisanie.xlsx  (заменяется)   │
  └──────────┘  (сайт GitHub,   │ data/config.json  (звонки, недели, праздники)│
                 можно с        │        │ push → GitHub Action                │
                 телефона)      │        ▼                                     │
                                │  pytest → парсер → валидация                 │
                                │        │ всё ок?  нет → публикации нет,      │
                                │        │          письмо владельцу           │
                                │        ▼ да                                  │
                                │  GitHub Pages:                               │
                                │   index.json  groups/*.json  ics/*.ics       │
                                │   diff/latest.json   index.html (подписка)   │
                                └────────┬───────────────────────┬─────────────┘
                                         │ HTTPS + ETag          │ webcal://
                                         ▼                       ▼
                           ┌──────────────────────────┐  ┌─────────────────────────┐
                           │ Android (Flutter)        │  │ iPhone: Календарь       │
                           │ офлайн-кэш, ДЗ, виджеты  │  │ (подписка .ics, сама    │
                           │ уведомления              │  │ обновляется + виджет    │
                           └──────────────────────────┘  │ «Календарь»)            │
                                                         └─────────────────────────┘
```

**Принципы**
1. **Offline-first.** Приложение показывает данные из локального кэша, а в сеть ходит только за обновлениями.
2. **Один источник истины.** Расписание разбирается только парсером на Python. Приложение и календари получают уже готовый JSON и не разбирают xlsx сами.
3. **Конфигурация, а не код.** Звонки, дата отсчёта недель, праздники и исправления опечаток лежат в `config.json`.
4. **Сломанный файл не публикуется.** Пользователи продолжают видеть последнюю хорошую версию.

## 4. Алгоритм парсера

Сначала для каждого листа строим `MergedSheet`: словарь `(строка, столбец) → область объединения`. Для необъединённой ячейки область — сама эта ячейка. Функция `text(r, c)` возвращает значение **левой верхней** ячейки области, причём пробельные символы схлопнуты в один пробел и обрезаны по краям.

```
Для каждого листа из config.sheets:
 1. Строка заголовка H — первая строка, где есть ячейка с текстом «дни недели» (без учёта регистра).
    day_cols — все столбцы строки H с этим текстом.
    first_data_row — строка сразу под областью ячейки «Дни недели».

 2. Строка групп G — первая строка в диапазоне [H, first_data_row), где есть ячейки,
    подходящие под GROUP_RE = r"[А-ЯЁа-яёA-Za-z]+-\d{2}\b".
    Строка подгрупп S — следующая строка в том же диапазоне, где тоже есть совпадения (может отсутствовать).

 3. Группы — левые верхние ячейки строки G, подходящие под GROUP_RE.
      name = текст без «(…)» в конце         → «1 БИ-25», «ОЗ-1 ИТиСС-26», «М-ИВТ-25»
      cols = столбцы области ячейки группы
      day_col = ближайший day_col левее группы
      course — по году в названии (§1.6)
      id = <код формы>-<транслит name>       → «ofo-1-bi-25», «ozfo-oz-1-itiss-26», «mag-m-ivt-25»

 4. Подгруппы группы:
      если строка S есть: каждая отдельная область строки S внутри cols — подгруппа
          (подпись = её текст или «Подгруппа N»);
      иначе: каждый столбец из cols — подгруппа «Подгруппа N»;
      нумерация 1..n слева направо.

 5. Слоты пар для каждого day_col: идём по строкам от first_data_row по столбцу «Часы»
    (day_col + 1). Ячейка вида «N-M» → слот {weekday, pair = M // 2, rows = строки её области}.
    Если область «Часов» в одну строку, а следующая строка в «Часах» пустая, слот берёт и её.
    weekday определяется по столбцу day_col (по первым 3 буквам: пон=1 … суб=6).

 6. Для каждой группы, слота и подгруппы (берём первый столбец подгруппы):
      t1, t2 = текст верхней и нижней строки
      t1 == t2 != ""  → week 0 (каждая неделя)
      иначе           → t1 → week 1, t2 → week 2 (пустые пропускаем)
    Записи с одинаковыми (week, текст) у разных подгрупп сливаются в одно занятие
    со списком subgroups.
    kind: «Физическая культура» → pe; «Кураторский час» → curator;
          область ячейки пересекает столбцы > 1 группы → lecture; иначе practice.
    После обработки всех слотов: если КАЖДОЕ занятие группы идёт для всех подгрупп
    и подписей подгрупп нет, схлопнуть их в одну.

 7. cell_text.parse(raw) → (subject, teacher, room, tags):
      a) применить config.subjectFixes;
      b) теги: «(юноши)» → male, «(девушки)» → female; убрать их из subject;
      c) аудитория в конце строки (\s* — пробел перед ней не обязателен):
         \d-\d{2,3}[а-я]? | \d\s*корпус | читальный зал(\s*\(.*?\))?
      d) преподаватель в конце оставшегося:
         Фамилия(-Фамилия)?\.? + пробел + инициалы вида «А.», «А.Х.», «М.С-У.», «М-Х.Р.», «А.А»
      e) остаток = subject. Если subject пустой — subject = raw.
      raw сохраняется всегда.
```

Отчёт `public/report.txt`: число групп по листам, число занятий, список ячеек, где не нашлись преподаватель или аудитория.

**Валидация** (`validate.py`) — при нарушении код выхода ≠ 0, и публикация не происходит:
- на каждом листе найдено > 0 групп; суммарно групп не меньше 90 % от прошлой публикации;
- доля ячеек с распознанным преподавателем ≥ 95 %;
- у каждой группы ≥ 1 занятие;
- число занятий изменилось не больше чем на 40 % относительно прошлой версии (иначе это скорее сломанный файл, чем новое расписание).

**Diff** (`diff.py`): скачивает прошлый `index.json` и `groups/*.json` с Pages (URL задаётся в `config.json`) и сравнивает по ключу `(groupId, weekday, pair, week, subgroups)`. Результат — `diff/latest.json`: список «добавлено / удалено / изменено (поле: было → стало)» по каждой группе.

## 5. Форматы данных

### 5.1 `config.json`
```json
{
  "academicYearStart": 2026,
  "semester": { "id": "2026-autumn", "start": "2026-09-01", "end": "2026-12-26" },
  "weekAnchor": "2026-08-31",
  "timezone": "Europe/Moscow",
  "bells": [["09:00","10:30"],["10:40","12:10"],["13:00","14:30"],["14:40","16:10"],["16:20","17:50"]],
  "holidays": [],
  "sheets": { "ОФО": {"code": "ofo",  "title": "Очная"},
              "ОЗФО": {"code": "ozfo", "title": "Очно-заочная"},
              "Магистратура ОФО": {"code": "mag", "title": "Магистратура"} },
  "subjectFixes": { "Аккаутинг": "Аккаунтинг", "проодаж": "продаж",
                    "специальсность": "специальность", "Интерет": "Интернет" },
  "source": "sources/raspisanie.xlsx",
  "publicBaseUrl": "https://<github-логин>.github.io/raspisanie/"
}
```
`semester.end` = 26.12.2026 подтверждён владельцем. `holidays` — пустой список: по решению владельца праздничные дни до конца семестра не учитываются (все желающие сами разберутся). Механизм остаётся: любая дата из `holidays` исключается из календарей, приложения и поиска.

### 5.2 `index.json` (несколько КБ, приложение скачивает его первым)
```json
{
  "schemaVersion": 1,
  "version": "2026-10-08T16:36:00Z-a1b2c3d4",
  "semester": {"id": "2026-autumn", "start": "2026-09-01", "end": "2026-12-26"},
  "weekAnchor": "2026-08-31",
  "timezone": "Europe/Moscow",
  "bells": [["09:00","10:30"], "..."],
  "holidays": [],
  "forms": [
    { "code": "ofo", "title": "Очная",
      "groups": [
        { "id": "ofo-1-bi-25", "title": "1 БИ-25", "course": 2,
          "subgroups": [{"n": 1, "label": "БИ-25-1"}, {"n": 2, "label": "БИ-25-2"}],
          "hasGenderedPe": true,
          "hash": "9f2c…" }
      ] }
  ]
}
```
`hash` — хеш содержимого файла группы. Приложение перекачивает файл группы, только если хеш изменился.

### 5.3 `groups/<id>.json`
```json
{
  "schemaVersion": 1,
  "version": "2026-10-08T16:36:00Z-a1b2c3d4",
  "group": { "id": "ofo-1-bi-25", "title": "1 БИ-25", "form": "ofo", "course": 2,
             "subgroups": [{"n": 1, "label": "БИ-25-1"}, {"n": 2, "label": "БИ-25-2"}] },
  "lessons": [
    { "weekday": 3, "pair": 4, "week": 2, "subgroups": [1],
      "kind": "practice", "subject": "ЧТК и этика", "teacher": "Ахмадова М.П.",
      "room": "2-15", "tags": [], "raw": "ЧТК и этика Ахмадова М.П. 2-15" }
  ]
}
```
Значения полей: `weekday` 1–6 (Пн–Сб); `pair` 1–5; `week` 0 = каждая неделя, 1 или 2; `kind` ∈ `lecture | practice | pe | curator`; `tags` ⊂ `male | female`; `teacher` и `room` могут быть `null`.

### 5.4 Календари `ics/<groupId>-<n>[-m|-f].ics`

- Файл на каждую подгруппу. Если у группы физ-ра делится на юношей и девушек, создаются 3 варианта: без суффикса (обе), `-m` (юноши), `-f` (девушки).
- **Без RRULE: каждое занятие — отдельное событие на конкретную дату** от `semester.start` до `semester.end`, с учётом номера недели и без `holidays`. Так проще и надёжнее во всех календарях.
- Время в UTC (`DTSTART:20261007T114000Z`).
- `UID` стабильный: `<groupId>-<n>-<YYYYMMDD>-<pair>@raspisanie`. Тогда при обновлении календарь *обновляет* событие, а не создаёт дубликат.
- `SUMMARY`: `ЧТК и этика · практика`. `LOCATION`: `2-15`. `DESCRIPTION`: преподаватель, «2 неделя», исходный текст.
- В заголовке: `X-WR-CALNAME:1 БИ-25 · подгруппа 1`, `X-WR-TIMEZONE:Europe/Moscow`, `REFRESH-INTERVAL;VALUE=DURATION:PT6H`, `X-PUBLISHED-TTL:PT6H`.
- Строки длиннее 75 байт переносятся по RFC 5545; `,`, `;`, `\`, переводы строк экранируются.

### 5.5 Страница подписки `index.html` (для iPhone и всех остальных)

Статическая страница без сборки, на vanilla JS. Она читает `index.json` и проводит пользователя по шагам: форма → курс → группа → подгруппа → физ-ра. Затем показывает:
- кнопку **«Добавить в Календарь iPhone»** (`webcal://<host>/<path>/ics/…`);
- кнопку **«Добавить в Google Календарь»** (`https://calendar.google.com/calendar/r?cid=webcal://…`);
- таблицу расписания на неделю (1 и 2 неделя) для проверки;
- короткую инструкцию с картинками: как добавить виджет «Календарь» на экран iPhone;
- ссылку на скачивание APK для Android.

Страница адаптирована под телефон и поддерживает тёмную тему.

### 7.3 Ядро — `ScheduleResolver`

```dart
List<ResolvedLesson> resolve(DateTime date, GroupSchedule s, UserProfile p, List<Override> overrides)
```
1. Если дата — воскресенье, праздник или вне семестра → пустой список.
2. Оставить занятия, у которых `weekday == date.weekday` и `week ∈ {0, weekNumber(date)}`.
3. Оставить занятия, где `p.subgroup ∈ subgroups`.
4. Физ-ра: если в профиле выбрано `male` или `female`, убрать занятия с противоположным тегом.
5. Применить личные правки на эту дату: `cancel` — убрать пару, `replace` — подменить поля, `add` — добавить пару.
6. Проставить `startAt` / `endAt` по звонкам и отсортировать по номеру пары.

Функция чистая: не обращается ни к сети, ни к UI, ни к часам напрямую. Покрывается юнит-тестами на контрольных фактах из §11.

`homework_due.nextOccurrence(subject, after, {kind})` — ближайшая дата после `after`, когда `resolve` возвращает занятие с этим предметом (и, если указан, нужного типа). Поиск идёт не дальше 28 дней вперёд.

### 7.5 Синхронизация

- **При запуске:** сразу показать кэш, затем фоном запросить `index.json` с `If-None-Match`. Ответ 304 — ничего не делать. Ответ 200 — сравнить `hash` своей группы и при изменении скачать файл группы.
- **Фоном:** `workmanager` раз в ~6 ч делает то же самое.
- **При изменении расписания** (`diff/latest.json`): показать уведомление «Расписание обновилось: 2 изменения», а на экране «Сегодня» — баннер со списком изменений.
- **После любого изменения** (расписание, ДЗ, правки, смена профиля) пересобрать WidgetSnapshot и перепланировать уведомления.
- **Без сети** приложение работает полностью. Ошибки сети пользователю не показываются; есть только тихая метка «обновлено 2 дня назад».

### 7.6 Виджеты

Виджет не может обращаться ни к сети, ни к базе данных Flutter. Поэтому Flutter пишет через `home_widget` в SharedPreferences **`WidgetSnapshot` на 7 дней вперёд**:
```json
{ "generatedAt": "...", "weekLabel": "2 неделя",
  "days": [ { "date": "2026-10-08",
              "lessons": [ { "start": "2026-10-08T09:00+03:00", "end": "...", "pair": 1,
                             "short": "Упр. проектами", "subject": "Управление проектами",
                             "room": "2-21", "teacher": "Адымханов А.", "kind": "practice",
                             "hasHomework": true } ] } ] }
```
- Нативный Kotlin-виджет **сам смотрит на часы** и выбирает из снимка текущую или следующую пару.
- `WidgetAlarms.kt` ставит `AlarmManager.setWindow` на ближайшую границу пары и обновляет виджет.
- Обратный отсчёт делается через `Chronometer` и тикает сам, без перерисовки.
- Виджет корректен неделю без запуска приложения. Это важно на Xiaomi и Huawei, где фоновые задачи часто убиваются.

| Виджет | Содержимое |
|---|---|
| **2×2 «Сейчас / Далее»** | Короткое имя предмета, **аудитория самым крупным шрифтом**, «через 12 мин» / «до конца 35 мин», значок Л/П |
| **4×2 «Сегодня»** | Все пары дня, текущая подсвечена; после последней пары — «Завтра»; в углу «2 неделя»; кнопка «+ ДЗ» |

Нажатие на пару открывает приложение на этом дне, нажатие на «+ ДЗ» — `raspisanie://homework/new?subject=…`.

### 7.7 Уведомления

- **Перед парой** (по умолчанию за 10 мин, настраивается, можно выключить): «Философия → 3-01 · Кутаев А.Х.».
  Планируются на 7 дней вперёд через `zonedSchedule`; перепланируются после каждой синхронизации.
- **Вечером в 19:00**, если на завтра есть ДЗ: «На завтра 2 ДЗ: Аккаунтинг, Графический дизайн».
- **«Расписание обновилось»** с кратким списком изменений.

## 8. Экраны и UX

**Первый запуск** (около 10 секунд, без регистрации): форма → курс → группа → подгруппа (подсказка: «1 — левый столбец в таблице») → физ-ра (юноши / девушки) → готово. Все настройки можно потом поменять.

**«Сегодня»** (главный экран)
- Сверху: «**2 неделя** · четверг, 8 октября».
- Большая карточка текущей или следующей пары: предмет, **аудитория крупно**, преподаватель, бейдж «Лекция» / «Практика», полоска прогресса.
- Ниже — остальные пары дня. Окна между парами помечены («окно 1 ч 30 мин»), большая перемена отмечена.
- Значок рядом с предметом, если на это занятие задано ДЗ.
- Свайпом листаются дни. В воскресенье и после последней пары экран сразу показывает следующий учебный день.
- Пустой день: «Пар нет 🎉».

**«Неделя»** — переключатель 1 / 2 неделя (по умолчанию текущая); дни списком.

**ДЗ**
- Долгое нажатие на пару (или кнопка «+ ДЗ») → поле ввода. **Срок подставляется автоматически — следующее занятие этого предмета.** Можно уточнить «к практике» или «к лекции».
- Можно прикрепить фото доски.
- Список разбит на «Просрочено», «На завтра», «На этой неделе», «Позже»; свайп отмечает выполненное.
- В настройках — экспорт и импорт ДЗ в JSON-файл (на случай смены телефона).

**Поиск**
- Преподаватель — где он сейчас и его расписание.
- Аудитория — кто в ней занимается.
- **Свободные аудитории** на выбранную пару.
- Для этого нужны файлы всех групп: они скачиваются один раз (~сотни КБ) и обновляются по `hash`.

**Настройки:** группа, подгруппа, физ-ра, короткие названия предметов, уведомления, тема (системная / светлая / тёмная), ручной переключатель недели (на случай сбоя чередования), экспорт ДЗ, «О приложении».

**Визуальный стиль:** Material 3 + Material You (цвета из обоев на Android 12+). У каждого предмета постоянный цвет (по хешу названия). Тёмная тема. Аудитория — самый крупный текст в карточке.

## 10. Нефункциональные требования

- **Скорость:** холодный старт до экрана «Сегодня» < 1 с на среднем Android (данные из кэша).

- **Доступность:** контраст по WCAG AA, поддержка увеличенного системного шрифта, подписи для TalkBack.

- **Код:** понятные имена, аннотации типов в Python, короткие комментарии на русском там, где логика неочевидна. Никакой «магии», которую владельцу будет трудно поддерживать.

## 12. Риски

| Риск | Что делаем |
|---|---|
| Поменяется формат таблицы (сдвинутся строки или столбцы) | Ищем заголовки по тексту, а не по координатам; валидация + golden tests; сломанный файл не публикуется |
| Опечатки в ячейках | `raw` хранится всегда; `subjectFixes` в config; список проблемных ячеек в `report.txt` |
| Сдвинется чередование недель | `weekAnchor` в `config.json` / `index.json` — правка одной строки; в приложении есть ручной переключатель |
| Android убивает фоновые задачи | Виджет работает от снимка на 7 дней и будильников; уведомления запланированы заранее |
| Новый семестр — новый файл | Меняются `semester` и `weekAnchor` в config и сам xlsx; кэш приложения сбрасывается при смене `semester.id` |
| У iPhone нет приложения | Подписка .ics + виджет «Календарь»; нативное iOS-приложение можно сделать позже из того же Flutter-кода |
| ДЗ потеряется при смене телефона | Экспорт и импорт файлом |
